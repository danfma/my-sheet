## Design decision

**The bug.** The mini-CSE (`Danfma.MySheet/Expressions/ArrayEvaluation.cs`, operands in `ArrayOperands.cs`) requires two array operands to have EQUAL shapes: `ResultShape` (`ArrayEvaluation.cs:623-638`) gives a mismatched pair the per-axis maximum, and every array operand's `At` then refuses that extent with a per-element `#VALUE!` (`RangeOperand.At:84-87`, `PositionNumbersOperand.At:135-138`, `BinaryOperand.At:175-178`, `IfOperand.At:217-220` — four copies of `_rows != rows || _columns != columns`). Only a `ScalarOperand` broadcasts. Excel broadcasts vectors, and a 1x1 *range* is a vector too.

**Fixture (both engines).** `A1:C3` = 1..9 row-major (`A1`=1, `B1`=2, `C1`=3, `A2`=4, …, `C3`=9); `E1:E3` = 1,2,3 (column); `E5:G5` = 10,20,30 (row); `H1:H2` = 1,2 (column). Text cases use Phase 8's `Textual()` (`D7`="abc", `D8`="def", `E9`=" ", nothing else) and a `Broadcast` variant that adds `E6:E8` = 1,2,3 (which puts numbers at `E7`/`E8` INSIDE `D7:F9` — deliberate, see the LEFT rows).

**Which entry form governs.** The Aspose PLAIN-entry column below is legacy implicit intersection *inside the argument*: `SUM(A1:C3*E1:E3)` is `#VALUE!` there — the brief's "SUM consumes the array either way" is FALSE on the oracle; only SUMPRODUCT, INDEX, ROWS and COLUMNS are array-native under plain entry. MySheet's mini-CSE reproduces CSE semantics by design (that is the whole `plans/mini-cse-array-arguments.md`), so **the CSE column is the target** for every consumer; the plain column is reported only to make that choice explicit.

**The rule, as measured (not as the brief states it — the brief was right).** For each axis independently: an extent of 1 defers to the other operand (a 1x1 broadcasts everywhere; a 1xN row repeats down every row; an Nx1 column repeats across every column; Nx1 against 1xM is the NxM outer product); where BOTH extents exceed 1 and differ, the result takes the LARGER, and every position the shorter operand does not cover is **`#N/A`** — a per-element error, not a whole-expression one (`COUNT` = 6 of 9; `AGGREGATE(15,6,…)` skips them and answers 12; `IFERROR` recovers them). Error precedence is the operator's existing one: the left operand's own error beats the right operand's `#N/A` at the same position, and vice versa. `IF` broadcasts its condition AND both branches into one extent (`IF(E1:E3>1,E5:G5,0)` is 3x3; `IF(H1:H2>1,E5:G5,0)` is 2x3). `SUMPRODUCT`'s own dimension rule is untouched: its arguments must match exactly, a 1x1 included — but an argument that is itself a broadcast expression is consumed as the broadcast array, `#N/A` elements propagating (`SUMPRODUCT(A1:C3*H1:H2)` = `#N/A`).

**The design: one resolver, `Danfma.MySheet/Expressions/Broadcasting.cs`, two entry points.** `internal static class Broadcasting` with (a) `Axis(a, b)` = `a == 1 ? b : b == 1 ? a : Math.Max(a, b)`, `Extent(rowsA, columnsA, rowsB, columnsB)` and `Fold(ref rows, ref columns, ArrayOperand)` — the BUILD-time half, replacing `ResultShape`'s body and Phase 8's item-8 fold; (b) `TryProject(index, rows, columns, ownRows, ownColumns, out ownIndex)` — the READ-time half: given the consumer's row-major `index` in the `rows`×`columns` extent, the operand's OWN row-major index, or `false` when the position is uncovered. Equal shapes are two comparisons and `ownIndex = index` — no division on the path every existing formula takes; otherwise decompose once (`row = index / columns`, `column = index % columns`), an axis of extent 1 forces its coordinate to 0 (row vector → ignore `row`; column vector → ignore `column`; 1x1 → constant), a coordinate at or beyond the operand's extent is uncovered. Every array operand's `At(index, rows, columns)` becomes: `if (!Broadcasting.TryProject(…, _rows, _columns, out var own)) return ComputedValue.Error(Error.NA);` then its existing body over `own` — a composite (`BinaryOperand`, `IfOperand`, Phase 8's two) hands `own` to its children **with its own extent** (`_left.At(own, _rows, _columns)`), so nested broadcasting composes: `(A1:A3*H1:H2)*E5:G5` is a 3x1 child inside a 3x3 parent, and the child projects the parent's index before its own children project the child's. `ScalarOperand` is untouched (it ignores the shape). `ArrayStream.Rows`/`Columns` stay what they are — the ROOT operand's extent, now a broadcast extent — so `PositionalRange`'s transpose, `Index`'s bounds and `TryEvaluate`'s vector need no change. Row-major streaming order is preserved because the consumer still walks `0 .. rows*columns-1` of the root extent. Zero allocation per element is preserved because the projection is integer arithmetic on the stack (`[MethodImpl(AggressiveInlining)]` on `TryProject`; measured below). The error precedence falls out of `BinaryOperation.Apply`'s existing left-then-right rule once each side answers `#N/A` for itself.

**Alternatives rejected.** (1) Keep `#VALUE!` per element and document it — simpler-but-different, forbidden by P0. (2) A `BroadcastOperand` adapter wrapped around each child at build time — allocation-free too, but it adds a virtual hop per element per child and puts the shape decision in a SECOND place beside the operands' own guards, which is what Phase 8's "do not write a second one" forbids. (3) A resolver returning per-operand index-mapper delegates — one indirect call per element per operand, and delegates allocate at build; `TryProject` is the same arithmetic with none of that. (4) Fixing `ResultShape` alone (1 defers to the other side) without touching `At` — measured on the prototype's first cut: the operands still refuse the extent, so nothing changes; the read-time half is where the semantics live.

## Risks carried by this phase

- **A new error kind enters every stream consumer.** `#N/A` elements now flow into `NumericAggregation.Fold`, `KthValueStreaming`, `CollectStream`, `Index` and `PositionalRange`. Each already treats any error element uniformly (first error in scan order propagates; option 6 skips), and the prototype confirms the consumer answers match Aspose (SMALL `#N/A`, AGGREGATE 12, SUMPRODUCT `#N/A`), but a consumer that special-cases `Error.Value` by name would silently diverge — grep for `Error.Value` in the consumers before closing the phase.
- **Failures become numbers.** A formula that today fails with `#VALUE!` because it multiplies a rectangle by a 1x1 range or a vector now computes. Every such case measured matches Aspose, so this is the fix — but a workbook whose cached value was the error will change value on recalculation, and there is no migration note channel except the CHANGELOG entry (`feat(eval):`).
- **Both files are Phase 8's battlefield.** `ArrayOperands.cs` and `ArrayEvaluation.cs` are rewritten in part by Phase 8 (two new operands, two new `Probe`/`TryBuildOperand` arms, an N-ary fold). This phase executes after Phase 9, so rebase onto the landed Phase 8 and edit its operands in place (item 8); the line numbers in this file are pre-Phase-8 and will be wrong by then — anchor on member names.
- **`IfOperand`'s extent widening changes which branch elements are READ.** A branch that is a 3x3 array under a 2x1 condition is now read for six positions instead of two; the extra reads are pure (`RangeOperand` cell reads through the memoized dense path) and volatile branches are still `ScalarOperand`s drawn once at build. `MiniCseVolatileTaintTests` is the guard.
- **Nested extents rely on every level projecting.** A composite operand asked at a larger extent than its own must project BEFORE asking its children with its OWN extent (items 6-8). A future operand that forwards the parent's `index` and extent to its children directly would read children at the wrong extent and get `#N/A` for covered positions; the `COUNT(A1:C3*H1:H2*E5:G5)` = 6 pin catches the first such mistake.
- **Docs now state a rule the criteria family does not follow.** `SUMIFS(A1:C3,A1:C3*H1:H2,">0")` stays `#VALUE!` here (Aspose: `#REF!`) — the "Not supported" bullet must keep saying arrays are refused there, or a reader will expect broadcasting to apply.
