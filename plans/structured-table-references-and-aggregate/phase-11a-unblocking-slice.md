**What must NOT move — the top-level name.** `NameReference` derives from `Expression`, not `Reference`, so every consumer gate written `is not Reference && IsArrayEligible(…)` would, the moment `Probe` says a name is an array, route a BARE top-level name into the mini-CSE. The union ruling already owns that shape.

**The rule.** *A name in an array position is whatever it is bound to; at a consumer's top level a bare name is a reference and takes the reference path, exactly as a bare literal range does.* Prototype (three files, no new type): `Probe` gains `case NameReference` immediately after `case OpenRangeReference` (before the `Row`/`Column` arms — different node types, no shadowing; Phase 7 item 2 inserts its `IArrayProducer` arm before `default:`) mapping a private four-way helper `ResolveNameShape(expression, context, out resolved)` — `NamedReferences.TryResolveReference(…, boundOpenRanges: false)` false → **Opaque** `(true, false)` (a constant, a formula name, an unknown name — `#NAME?` still flows through the scalar path); `RangeReference`, **including one whose sheet is missing** → **Range** `(true, true)` (B2: `BuildRange` streams the per-element `#REF!`, so `SUM` → `#REF!` and `COUNT` → 0 like the literal and the oracle); `OpenRangeReference` → **Refused** `(false, false)` (the cost guard); a single cell or a union → **Scalar** `(true, false)`. `TryBuildOperand` mirrors it: Range → `BuildRange((RangeReference)resolved, context)`; Refused → `false`; Scalar → `new ScalarOperand(resolved.Evaluate(context))`; Opaque → `new ScalarOperand(expression.Evaluate(context))`. The three top-level gates exclude a bare `NameReference` exactly as they exclude a bare `Reference`. Prototype result on the full core suite (with Rule B applied too): **4 failed / 1578** — exactly the three deliberate-divergence tests named in item 4 (one reported twice by the runner). Cost: one resolution in the probe and one in the build per name node per evaluation, the same double resolution `ResolvePositionRange` documents.

### Rule B — a criteria-family range slot rejects a computed array with `#REF!` (item 22)

**The bug at `0b93d66`.** `PositionalRange.Open` (`CriteriaScan.cs`) is deliberately not `OpenArrayOrRange`, so a computed array in a criteria slot falls to `ArgumentFlattening.ExpandComputedValues` and collapses to one `#VALUE!` element; single-range forms then report an empty scan. Measured, same fixture (`Rng` bound), MySheet `0b93d66` → proto, then oracle plain / CSE: `SUMIF(A1:A3*1,">0")` **0** → `#REF!` (`#VALUE!` / **`#REF!`**); `COUNTIF(A1:A3*1,">0")` **0** → `#REF!` (same); `COUNTIFS(A1:A3*1,">0")` **0** → `#REF!` (same); `AVERAGEIF(A1:A3*1,">0")` `#DIV/0!` → `#REF!` (same); `SUMIFS(B1:B3,A1:A3*1,">0")`, `AVERAGEIFS(…)`, `MAXIFS(…)`, `MINIFS(…)` `#VALUE!` → `#REF!` (same); the VALUE slots `SUMIF(A1:A3,">0",B1:B3*1)` **0**, `AVERAGEIF(A1:A3,">0",B1:B3*1)` `#DIV/0!`, `SUMIFS(A1:A3*1,B1:B3,">0")` `#VALUE!`, `MAXIFS(B1:B3*1,A1:A3,">0")` `#VALUE!` → `#REF!` each (same); the second pair `COUNTIFS(A1:A3,">0",B1:B3*1,">1")` `#VALUE!` → `#REF!` (same); `COUNTIF(ROW(A1:A3),">1")` **0** → `#REF!` (**`#REF!` / `#REF!`**); `COUNTIF(-A1:A3,"<0")`, `COUNTIF(LEN(A1:A3),">0")` **0** → `#REF!` (`#VALUE!` / `#REF!`); `COUNTIF((Rng<>0)*1,">0")` **1** → `#REF!` (`#VALUE!` / `#REF!`, needs Rule A first); `COUNTIF(IF(A1:A3>4,A1:A3,B1:B3),">0")` **0** → `#REF!` (`#VALUE!` / 2 — the M7 first-element artifact the user's ruling already refuses to reproduce). **Unchanged, measured on the prototype:** `COUNTIF(IF(TRUE,A1:A3,B1:B3),">0")` 0 (2 / 2; item 9's), `COUNTIF(CHOOSE(1,A1:A3,B1:B3),">0")` 2, `COUNTIF(OFFSET(A1,0,0,3,1),">0")` 2, `COUNTIF(Rng,">0")` 2, `SUMIF(Rng,">0",B1:B3)` 4, `MINIFS(B1:B3,Rng,">0")` 1, `MAXIFS(B1:B3,A1:A3,">0")` 3, `SUMIFS(B1:B3,A1:A3,">0",B1:B3,">1")` 3, `COUNTIF(A1,">0")` 1, `COUNTIF(A:A,">0")` 2, `COUNTIF(MyCell,">0")` 0 (0 / 0), `COUNTIF(GhostName,">0")` `#REF!`, `SUMPRODUCT((A1:A3<>0)*1)` 2 and `SUMPRODUCT(A1:A3*1,B1:B3)` 32 (SUMPRODUCT's opt-in factory is untouched), and the two scalar shapes `COUNTIF(A1*1,">0")` = `COUNTIF(5,">0")` = 1 (`#REF!` / `#REF!` — the sweep's scalar rule) and the open-range `SUMIF(A:A*1,">0")` = 0 (`#REF!` / `#REF!` — the cost guard refuses the operand, so it is not "array-eligible").

**The rule.** *A range slot of `SUMIF`/`SUMIFS`/`COUNTIF`/`COUNTIFS`/`AVERAGEIF`/`AVERAGEIFS`/`MAXIFS`/`MINIFS` — criteria range, sum/average/max/min range alike — that is not a reference node and that the mini-CSE would stream is `#REF!`.* That is the CSE column for a computed array and BOTH columns for a producer; `#REF!` over `#VALUE!` is therefore not a cross-mode comparison but the only value both producer columns agree on. The predicate is exactly `TryStream`'s gate, `argument is not (Reference or NameReference) && ArrayEvaluation.IsArrayEligible(argument, context)`, so a scalar-conditioned `IF`, `CHOOSE`, `OFFSET`, a name, a cell, a bare scalar and a refused open range are all untouched. Prototype: one static helper on `PositionalRange` returning `Error?`, checked before each of the **eight** `Open` calls — `SumIf.cs` (range, sum_range), `Statistical/ConditionalAggregates.cs` `AverageIf` (range, average_range), `CriteriaScan.CreateWithValue` (value range, each criteria range — feeds `SUMIFS`/`AVERAGEIFS`/`MAXIFS`/`MINIFS`), `CriteriaScan.CreateCountOnly` (each criteria range — `COUNTIFS`), `Statistical/CountIf.cs` (`RangeValueCursor.Open`).
